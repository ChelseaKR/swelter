# Internationalization conformance

swelter ships resident-facing English and Spanish in both the dashboard and generated alerts, so the
portfolio internationalization standard applies.

Owner: Chelsea Kelly-Reif. Last verified: 2026-07-17. Recheck cadence: every
resident-facing copy, catalog/runtime, locale, formatting, or language-review change.

## Catalog and runtime model

### Browser: Unicode MessageFormat 2

- `web/i18n/en.json` is the reference dashboard catalog and `web/i18n/es.json` is the Spanish
  catalog. Each contains the same **395** message keys. The JSON container is a flat key/string map;
  message values use Unicode MessageFormat 2 (MF2), including `.input`, `.match`, `one`, and the
  required `*` fallback for count selection.
- `web/i18n/messages.manifest.json` is generated from the HTML and JavaScript call sites. The
  extraction check rejects missing, unused, or unbounded dynamic keys, catalog-key drift, placeholder
  drift, invalid MF2, and a return to ICU MessageFormat 1 syntax.
- The application uses the canonical Unicode MF2 implementation from exactly
  `messageformat@4.0.0`. The lockfile records the exact tarball and integrity, and the install
  step copies the package runtime into `web/vendor/messageformat/`; the published page makes no
  external runtime request.
- The pin is the stable `4.0.0` release, resolved from the npm registry with its recorded tarball
  and integrity. The build fails closed if that exact package cannot be installed or its generated
  runtime cannot be checked.
- Number and date presentation continues through the browser's locale-aware `Intl` implementation.
  The active BCP-47 tag is reflected on `<html lang>` and direction is updated with it.

**Stable-runtime upgrade, completed 2026-07-31:** the earlier `4.0.0-11` prerelease pin, adopted when
no networked install could resolve the stable tarball, has been replaced by stable
`messageformat@4.0.0`. The npm lockfile and the generated `web/vendor/messageformat/` runtime were
regenerated from that release, and the i18n extraction, JavaScript unit, and browser suites were
rerun against it. The recorded package `engines` range is `^20.19 || ^22.12 || >=24`, which the
pinned Node 22.12 floor in `web/.nvmrc` satisfies. ADR 0026 remains the accepted vendoring decision;
only the version it names changed, so its stated `4.0.0-11` pin now reads as historical.

### Python alerts: gettext

- Extractable alert templates live in `src/swelter/i18n_alerts.py`. Babel **2.18.0** extracts the
  canonical `src/swelter/locales/alerts.pot`; complete `en` and `es` PO files live under
  `src/swelter/locales/<locale>/LC_MESSAGES/alerts.po`, with compiled MO files beside them.
- Python uses the standard-library `gettext` runtime. Unsupported locale tags fail safely to English;
  machine-facing translation labels and the operator-facing CLI remain fixed and are not silently
  localized.
- `scripts/gettext_catalog_check.py` re-extracts the POT and requires exact POT/PO message-id parity,
  complete translations, placeholder parity, no PO-format errors, and byte-for-byte equality between
  a fresh compilation and every committed MO file.

## Human review

Mechanical parity proves that a string exists, not that Spanish copy is accurate, natural,
culturally appropriate, or equally understandable. The current release needs a named independent
Spanish reviewer to exercise:

- Now/Explore orientation and navigation;
- source, freshness, provisional/calibrated, uncertainty, AQI-window, model/estimated, and missing-
  data language;
- alerts, watches, guidance context, cooling-center/context layers, and share/export copy;
- number/date/unit formatting and text expansion at narrow/reflow layouts;
- error, empty, loading, stale, offline, and source/license states.

Record reviewer, date, build/commit, tasks, findings, and disposition. Issue
[#106](https://github.com/ChelseaKR/swelter/issues/106) tracks this current signoff. Catalog parity,
machine translation, or an English accessibility review must not close it.

## Adding another locale

1. Add a complete catalog named with a valid BCP-47 tag and add the language control/manifest support.
2. Make extraction, MF2 parsing, placeholder, direction, and parity gates discover and validate it;
   include every plural category the locale needs plus the MF2 `*` fallback.
3. Test number/date/unit formatting, text expansion, keyboard/screen-reader behavior, mixed-direction
   content, and offline/static routing.
4. Obtain an independent fluent review of critical health/source/caveat content.
5. Update the ACR, acceptance-test map, data/publication docs, and this file in the same change.

Server-side `Accept-Language` negotiation is currently N/A because the public dashboard chooses a
static client catalog and alert feeds have explicit language routes. If negotiation is added,
responses must set appropriate cache variation and fallback behavior.
