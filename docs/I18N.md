# Internationalization status: in scope

swelter renders resident-facing heat, air-quality, alert, and trust copy in **English and
Spanish**, so it is **in scope** for `STANDARDS/INTERNATIONALIZATION-STANDARD.md`. This file records
the catalog format and which of the standard's §4 AUTO-GATES are live in `make verify` (and CI) —
each one mechanically checkable and merge-blocking.

## Catalog format

- **Location:** `web/i18n/en.json` (reference) and `web/i18n/es.json`.
- **Shape:** flat JSON `{ "key": "string" }`; keys are referenced from the dashboard via
  `data-i18n` / `data-i18n-attr` attributes in `web/index.html` and `t("key")` calls in
  `web/app.js`. The active locale is stored on `<html lang>` and persisted as a user preference.
- **Authored locale tags:** `en`, `es` (plus `<html lang="en">` and the web manifest `"lang"`).
- **Not gettext/PO yet.** The Python package emits no natural-language resident output (its date
  output is fixed-format UTC, not localized), so there is no server-side catalog to compile. If the
  Python surface ever renders localized strings, wrap them in `gettext` `_()` and the PO gates (G7)
  activate — see the standard's §4 PO gate.

## Live AUTO-GATES (`make verify` → target `i18n`, mirrored in CI)

| Gate | Rule | Mechanism | Status |
|---|---|---|---|
| **G1** UTF-8 | every tracked text file is `utf-8`/`us-ascii` | `scripts/i18n_encoding_check.py` (`git ls-files` + `file --mime-encoding`) | **live** |
| **G3** BCP-47 | every authored locale tag is well-formed + registered | `scripts/i18n_bcp47_check.py` (RFC 5646 grammar + ISO 639-1 registry) | **live** |
| **G4** html-lang | root `lang` present **and** a valid tag | `html-has-lang` in `scripts/a11y_check.py` (structural, pre-existing) + `html-lang-valid` folded into `scripts/i18n_bcp47_check.py` (blocking); also covered by the advisory axe pass | **live** |
| **G6** EN/ES key-parity | `keys(en) == keys(es)`, no empty ES values | `scripts/i18n_parity.py` + `tests/test_i18n.py` (also placeholder parity, G5) | **live** (prior PR) |
| **G12** CLDR/ICU pin | any bundled CLDR/ICU/`babel` dep meets the freshness floor (`babel>=2.16`, ICU/CLDR `>= 48.2`) | `scripts/i18n_cldr_pin_check.py` | **live guard — N/A-until-used** |

### G12 — N/A-until-used, explained

swelter does locale-aware date formatting, but only through the browser's built-in
`Intl.DateTimeFormat` (`web/app.js`). That CLDR/ICU data is the **browser's**, kept fresh by the
vendor and not pinnable from this repo; the Python side bundles no `babel`/`pyicu` and there is no
`web/package.json`. So there is **no in-repo CLDR/ICU version to assert today** — the gate passes by
delegation. `scripts/i18n_cldr_pin_check.py` is wired as a durable guard: the moment a bundled
CLDR/ICU dependency is added (`babel`, `pyicu`, a JS CLDR package, …), it enforces the version floor
and blocks a stale or unpinned pin.

## Not yet wired (later phases, tracked by the standard)

- **G2** no hardcoded UI strings (extraction ratchet) — deferred to a dedicated extraction phase.
- **G5** full CLDR plural categories — placeholder parity is enforced by `tests/test_i18n.py`;
  plural-category coverage lands with G2.
- **G7** PO compilation, **G8** XLIFF, **G9** pseudolocale overflow, **G10** RTL logical-CSS,
  **G11** `Vary: Accept-Language` — activate if/when the matching surface exists (PO catalogs, an
  XLIFF, an RTL locale, a negotiated server). None apply to the current static-catalog dashboard.
